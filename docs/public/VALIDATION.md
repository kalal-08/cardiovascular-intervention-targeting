# Validation and limitations

## Final local review — 2026-10-08

A bounded background-warming trial was removed after a responsiveness regression exceeded the agreed limit, despite faster prepared navigation. The retained foreground build matches the verified candidate. Fresh checks passed cache recovery, all five page contracts, header/keyboard and five-route browser integration, viewport cases and served-data integrity. No background warming or production speed improvement is claimed; the retained loading changes still require a separate production promotion.

## Foreground loading — 2026-10-07

Local production-build Edge checks cover five runs per loading/navigation scenario: 50 cold loads, 200 independent first navigations, 200 repeats and 360 control changes, plus targeted noisy-result rechecks. Cold-readiness medians improved in both tested profiles; the agreed cold and p95 regression gates passed. No duplicate dataset downloads, repeat-navigation application requests or JavaScript page errors were observed. Uncompressed localhost timings are not production estimates or official INP; cached-navigation variability does not support an instant-navigation claim.

Focused regressions verify fresh successful requests after transient manifest/schema/dataset failures, parallel download start without early consumption, and continued rejection of corrupt hashes or schema-invalid data. Existing header/integration browser checks also pass navigation/history, selectors, keyboard/focus and viewport cases; no screen-reader certification is claimed. Lazy-module failure is tested separately: document reload recovers, but data-cache eviction does not implement same-session module retry. Background and hover/focus warming remain deferred. These local changes are not deployed; historical production evidence below describes the accepted release.

## Run public checks

After the [web quick start](../../README.md#run-the-web-application-locally), from `web/`:

```powershell
npm.cmd run data:public:check
npm.cmd run typecheck
npm.cmd run build
npm.cmd run preview
# In another terminal while preview runs:
node scripts/check-data-http.mjs http://127.0.0.1:4173
```

Use `npm` instead of `npm.cmd` in other shells. These checks require only shipped public assets. Public-data regressions reject changed bytes, extra fields, duplicate keys, invalid types and missing/extra assets. Build excludes private Wrangler metadata and internal spike routes.

For scientific checks, follow [source acquisition and ordered regeneration](ANALYSIS_METHODS.md#scientific-reproduction) first. Data-dependent pytest cannot run against an app-only setup. Two `local_only` tests intentionally require excluded internal documentation; numerical and upstream-preservation checks remain applicable. Run the publication-boundary test in a Git checkout so ignore rules can be evaluated.

## Manual and historical browser evidence

The user accepted all five deployed pages after manual production review, including resizing and accessibility usability, on 2026-10-05. Monitor/laptop screenshots at the requested 100% zoom established the intended compact layout and natural scrolling on dense pages.

Earlier implementation-stage browser runs exercised navigation/history, selectors, sorting, tooltip/focus/touch access, loading errors and responsive/enlarged-text layouts. Those runs include fifteen Rollout policy/anchor states, 128 inspection capacities, 75 Robustness selector states, eighteen sorts and all 127 village rows. They were not rerun at the documentation-only checkpoint on 2026-10-05. The separately completed local header/integration suites and loading measurements on 2026-10-07 are described above; they do not recertify every historical case.

At the 2026-10-05 documentation-only checkpoint, the separate 65-case responsive browser regression was syntax-checked, not executed, under the user's then-current browser-automation restriction. That runner was not part of the completed 2026-10-07 header/integration suites, which included their own viewport cases. Its optional command, with separately provisioned Playwright and Edge, is:

```powershell
node scripts/check-responsive-browser.cjs http://127.0.0.1:4173 playwright
```

A screenshot, source check or HTTP response does not establish font rendering, animation smoothness, every device/browser or assistive-technology behavior. Short or narrow windows may scroll; universal one-screen fit and universal mobile optimization are not claimed.

## Known limitations

- Known text-contrast limitation accepted for this release; WCAG compliance is not claimed.
- Independent screen-reader, physical-device and Firefox/Safari certification is not claimed. The static Power BI PDFs are untagged.
- ECharts produces a known bundle-size warning; universal device-performance guarantees are not established.
- Manifest hashes check integrity against supplied metadata, not independent scientific authenticity. Different numerical-library/platform versions may change regenerated bytes.
- Scientific limits remain substantive: predicted-risk endpoint, missing outcomes, 127 clusters, pointwise model-conditional uncertainty, no established policy winner and no transportability or clinical/operational recommendation. See [methods](ANALYSIS_METHODS.md), [HTE validation](HTE_VALIDATION.md) and [rollout](ROLLOUT_AND_UNCERTAINTY.md).
